# Техническая проверка и её пределы

Проверки выполнялись без обучения, загрузки checkpoint в модель и научных inference/sweeps.
Численных новых исследовательских результатов этот комплект не содержит.

## Проверено

* 82 unit-теста на маленьких заданных массивах и простых математических полях.
* RMS/L2 эквивалентность, независимость частиц без взаимодействий, chain rule масштабированных координат.
* Maximum-cardinality/minimum-distance 1:1 matching, пустые множества, одна мода,
  один кандидат на две цели, дубликаты, localization и rare mask.
* Complete-linkage против single-linkage, mean/medoid, direction gate, fixed K, facility selection, empirical mean shift.
* Neural/analytic/diagnostic/intrinsic/actual счётчики, стоимость батчей и запрет превышения hard cap.
* Сохранение последнего завершённого шага при исчерпании бюджета; clipping и отключённая projection.
* Небольшие FD Split-проверки с исходными классами: число проверок/детей, фактический v3f1 criterion,
  независимость накопленного счётчика от legacy reset.
* Score/Hessian GMM против конечных разностей, простые одно-/двухмодальные примеры,
  вырожденный случай, воспроизводимость генерации и фиксированная относительная разделённость.
* Порядок RNG старого GaussianMixture.random сравнён с исходным классом на маленькой смеси.
* 25 JSON-конфигов полностью разворачиваются и проходят валидацию; старые пути не предполагаются существующими.
* Внешние блоки импортируются без исполнения; dry-run не запускает job и не пишет файлы.
* NPZ roundtrip без pickle, hashes, защита completed job, несовместимого resume,
  concurrent writer, выхода из каталога, symlink traversal и перезаписи протокола.
* Фиксация confirmation, отказ без lock и при изменении кода.
* Повторное использование нового кэша и импортированного префикса стартов с проверкой checkpoint identity;
  cache=false заново начисляет реальные искусственные вызовы.
* Cluster-aware bootstrap, отсутствие выдуманного CI при одном запуске, парные разности,
  отказ при разных стартах, Pareto и midrank support.
* Ретроспективный manifest проверен на крошечном явно заданном NPZ; отсутствие архива не создаёт результатов.

В среде разработки нет torch/torchvision. Поэтому технические тесты исходных математических
legacy-ядер компилируют **неизменённые class AST из проверенного репозитория**, исключая только
неиспользуемый импорт torch; модель и самплер при этом не конструируются. В production используются
обычные импорты исходных классов, и torch нужен. Это не подмена learned score тестовым score
в исследовательских результатах: тестовые поля существуют только в unit-тестах.

## Что не проверено научным запуском

* Загрузка и выполнение конкретных `.pth/.pt` на PyTorch/MPS; веса читались только как файлы/по коду их схем.
* Качество, покрытие, выигрыш методов, правильность научных гипотез и оптимальные параметры.
* Реальная скорость, VRAM/MPS memory и runtime больших FD-гессианов/полного MNIST kNN.
* Итоговые графики по новым данным: они появятся после запусков автора.
* Пересчёт старого recall/F1/SoftError при новых радиусах из Git-снимка без сырых координат.
* Побитовая воспроизводимость между версиями PyTorch, CPU и MPS.
* Полнота численного эталона для общих K>2 / неодинаковых ковариаций.

Это явные границы проверки. Технические PASS не служат свидетельством научного преимущества.

## Как повторить

Из корня проекта, с core dependencies:

```bash
python -m unittest research_experiments.tests.test_core -q
python -m research_experiments.run run \
  --config research_experiments/configs/09_mnist_diagnostics.pilot.json --dry-run --max-jobs 1
```

Финальный патч проверяется `git apply --check` на чистом снимке указанного commit,
затем применяется в проверочную копию. Хэши исходных файлов должны остаться неизменными,
а добавленные файлы — совпасть с новой директорией. Эти действия не требуют научного запуска.
